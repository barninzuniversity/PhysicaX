# SCIENTIFIC_VALIDATION.md — PhysicaX
## Purpose
PhysicaX is not a toy calculator. It is a computational science platform.
Scientific correctness and transparency are core requirements.
This document defines the minimum scientific standards for all numerical and  
physics modules.
## Core Standards
Every scientific module must include:
1. Explicit assumptions
2. Input validation
3. Reference tests
4. Invariant tests where applicable
5. Numerical stability considerations
6. Warnings for invalid or unstable regimes
7. Versioned result schemas
8. Reproducibility metadata when randomness is involved
## Formula Governance
- Standard textbook formulas only unless explicitly documented otherwise
--- page 182 ---
- Every nontrivial formula should be accompanied by:
  - a code comment
  - an assumption note
  - a test case
- Sign conventions must be documented clearly
- Units must be consistent and validated where feasible
## Floating-Point Standards
- Use tolerances in assertions
- Do not compare floats directly
- Tolerances should be chosen based on:
  - solver method
  - step size
  - conditioning of the problem
- When exact solutions exist, compare against analytical values
## Thermodynamics Standards
Must validate:
- ideal gas consistency
- physically valid state values (P > 0, V > 0, T > 0, n > 0)
- process-specific required parameters
- entropy handling only under stated assumptions
- sign conventions for work/heat must be consistent across the platform
Recommended tests:
- Isothermal ideal gas: ΔU = 0
- Isochoric: W = 0
- Adiabatic reversible: PV^ γ approximately constant
- Polytropic special-case sanity checks
## Mechanics Standards
Must validate:
- physically valid masses, lengths, damping coefficients
- solver stability under selected timestep
--- page 183 ---
- singular or degenerate parameter cases
Recommended tests:
- projectile without drag matches analytical trajectory/range
- undamped oscillator approximately conserves energy
- damped oscillator energy decreases monotonically
- small-angle pendulum matches linear approximation for small amplitudes
## Chaos / Nonlinear Dynamics Standards
Must validate:
- bounded iteration counts
- safe parameter ranges
- deterministic seeds when sampling or thinning data
- explicit transient discard / burn-in behavior
Recommended tests:
- logistic map at r=2.9 converges to fixed point
- logistic map at r=3.2 shows period-2 behavior
- logistic map at r 4 has positive Lyapunov estimate ≈
- Lorenz trajectory remains numerically bounded over standard test horizon
## Numerics Standards
ODE:
- Euler, Heun, RK4 should be tested on known systems
- RK4 should outperform Euler at equal step size in reference cases
- error behavior should improve as step size decreases
PDE:
- explicit methods must include CFL/stability checks
- warn on unstable discretization
- compare to analytical solutions where feasible (e.g. heat equation)
## Reproducibility Standards
When applicable, save:
--- page 184 ---
- solver method
- step size / timestep
- random seed
- truncation settings
- burn-in/transient settings
- schema version
- timestamp
- code version or engine version (future enhancement)
## Result Transparency
All results should include:
- assumptions
- warnings
- method/solver metadata
- version tags
- units
- limitations where relevant
## Educational Responsibility
The platform may include explanatory panels, but:
- explanations must not imply false certainty
- approximations must be labeled
- idealizations must be explicit
- numerical artifacts should be distinguishable from physical phenomena

export function solveEuler(
  f: ODEVectorField,
  y0: ODEState,
  options: ODESolverOptions
): ODESolution {
  const { t0, tEnd, dt } = options;
  const points = [{ t: t0, y: [...y0] }];
  let t = t0;
  let y = [...y0];
  while (t < tEnd) {
    const k1 = f(t, y);
    y = addScaled(y, k1, dt);
    t = Math.min(t + dt, tEnd);
    points.push({ t, y: [...y] });
  }
  return { method: "euler", points };
}
